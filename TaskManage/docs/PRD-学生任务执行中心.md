## 2. 产品摘要

### 2.1 产品定位

TaskManage 是面向高校学生的轻量执行中心。它将课程、作业、社团活动和个人目标统一呈现在“今天”视图中，在合适时间提醒用户完成、改期或重新规划，并通过及时、克制的反馈帮助用户看见自己的执行进展。

一句话价值主张：

> 把分散的课程和任务收进一个入口，在正确时间告诉学生下一步做什么，并让完成结果可见。

### 2.2 核心问题

| 问题 | 用户表现 | 根因 | 产品解法 |
|---|---|---|---|
| 任务入口分散 | 作业在群聊，课程在课表，社团在群公告，目标在备忘录 | 信息来源多，记录结构不统一 | 全局快速记录、收集箱、课程/活动关联、批量课表导入 |
| 提醒不统一 | 闹钟、日历、Todo 各自提醒，完成或改期后不同步 | 提醒与任务是两套数据 | 提醒绑定任务，完成/改期/删除时同步处理 |
| 完成后缺少反馈 | 勾选后任务消失，用户不知道是否持续进步 | 只有完成动作，没有阶段性总结 | 即时反馈、今日总结、周执行反馈、按期完成率 |
| 时间安排冲突 | 课程、活动和计划任务相互挤占 | 固定日程与可移动任务没有统一时间视图 | 日程/任务分层建模，硬冲突与负荷冲突提示 |

### 2.3 核心产品闭环

```text
信息出现
   ↓
快速创建 / 课表导入
   ↓
进入“任务 > 收集箱”或形成日程
   ↓
规划日期、时间、课程归属和提醒
   ↓
今天视图给出下一步行动
   ↓
完成 / 稍后提醒 / 改期
   ↓
即时反馈 + 今日总结 + 周反馈
   ↓
调整下一轮计划
```

## 3. 产品原则

1. **先收下，再整理。** 用户只填标题也能保存，不能因为字段过多阻断记录。
2. **统一视图，不混淆实体。** 课程、活动属于固定日程；作业、复习、目标属于任务。它们在“今天”统一展示，但底层结构不同。
3. **提醒必须有上下文。** 用户看到提醒时，应知道任务是什么、属于哪门课、何时截止，并能直接完成、稍后或改期。
4. **反馈帮助调整，不制造羞耻。** 不用夸张积分、排行榜或连续打卡惩罚用户；反馈重点是按期完成、合理改期和负荷变化。
5. **冲突提示默认不阻断。** 除非出现无效时间等数据错误，系统提供原因和调整建议，由用户最终决定。
6. **MVP 保持个人、轻量、离线可用。** 首版不引入团队协作、复杂项目管理和重型笔记编辑。

### 4.2 当前关键缺口

| 缺口 | 影响 | 处理优先级 |
|---|---|---|
| “今天”显示全部任务，而非真正的今日执行队列 | 用户仍需自己判断下一步 | P0 |
| 任务只有日期，没有截止时间、计划时间和预计耗时 | 无法做准确提醒和冲突判断 | P0 |
| 提醒与任务没有 `taskId` 关联 | 完成、改期、删除后提醒可能失效或残留 | P0 |
| 没有课程、学期、固定日程模型 | 无法实现课表和课程任务关联 | P0 |
| 日程页只是任务截止日期列表 | 无法呈现真实课表和活动时间轴 | P0 |
| 完成率按全部历史任务计算 | 随历史积累失真，不能形成有效反馈 | P0 |
| 本地账号保存原始密码 | 不能用于正式发布 | P0 发布门槛 |
| 本地存储无数据版本和迁移机制 | 扩展字段时存在数据丢失风险 | P0 |
| 原生提醒取消能力不完整 | 改期/删除后的通知可靠性不足 | P0 发布门槛 |
| 无埋点、自动化测试和设备提醒测试矩阵 | 无法验证闭环效果与稳定性 | P0 |
| UI 中英文混用 | 产品体验不统一 | P1 |
| 已移除镜子/手电筒，但清单仍声明相机权限 | 存在无必要权限申请风险 | P0 发布门槛 |

### 4.3 当前阶段判断

当前项目已经完成“可操作原型”，但尚未完成“可验证的学生任务闭环”。下一阶段不需要重写技术栈，应在现有 Vue 3 + uni-app + Pinia + Repository 结构上扩展领域模型，并优先打通任务、提醒、日程和反馈之间的数据关系。

当前“今天｜日程｜＋｜收集箱｜我的”导航和各页面布局属于已实现基线，不代表最终产品方案。目标信息架构和页面改造方案以第 8、10、12 节为准。

## 5. 目标用户与核心场景

### 5.1 核心用户

首版聚焦以下用户：

- 每周有多门课程、周期作业和考试安排的本科生。
- 同时参与社团、竞赛、实习或考研准备，任务来源较多。
- 当前使用群聊收藏、备忘录、课表应用、闹钟或通用 Todo 的组合。
- 不愿维护复杂数据库或项目管理系统，希望快速记录、自动提醒。

暂不针对：

- 需要团队任务分配和审批的社团管理者。
- 需要查看全班学情的教师。
- 需要复杂项目依赖、甘特图和工时管理的专业项目团队。

### 5.2 核心用户任务（JTBD）

| 场景 | 用户希望完成的事 | 成功结果 |
|---|---|---|
| 群聊收到作业 | 先快速记住，不打断当前活动 | 10 秒内保存，之后能在收集箱找到 |
| 新学期开始 | 快速建立课程表 | 一次导入或批量创建后形成每周固定日程 |
| 每天起床或下课 | 知道今天先做什么 | 5 秒内看到当前、下一项和临近截止任务 |
| 提醒到达 | 立即做出处理决定 | 可以直接完成、稍后提醒或改期 |
| 安排社团活动或复习 | 判断是否与课程冲突 | 保存前看到冲突对象和建议空档 |
| 一周结束 | 判断计划是否合理 | 看到按期完成率、延期分布和负荷高峰 |

## 6. 产品目标与非目标

### 6.1 MVP 产品目标

1. 用户能从任何主页面在 10 秒内记录一个任务。
2. 用户能在“今天”页面快速确定下一项行动。
3. 提醒与任务状态保持一致，避免重复提醒和失效提醒。
4. 用户可以对提醒直接执行“完成、稍后、改期”。
5. 用户能建立基础课程表，并在安排任务时获得时间冲突提示。
6. 用户可以看见今日和本周的真实执行结果。

### 6.2 MVP 非目标

- 不做团队协作、任务指派和群聊。
- 不做复杂文档、知识库和附件管理。
- 不做完整番茄钟或专注音乐。
- 不做排行榜、虚拟货币和强制连续打卡。
- 不承诺首版支持所有高校教务系统一键登录。
- 不做教师、学校或社团后台。
- 不做 AI 自动生成全部计划；AI 能力需在核心数据闭环稳定后评估。

## 7. 成功指标

### 7.1 北极星指标

**有效执行周用户数（Effective Weekly Executors）**：一周内至少在 3 个不同自然日完成过计划任务，且至少处理过一次提醒或改期的用户数。

该指标同时覆盖持续使用、执行行为和提醒闭环，避免只追求创建大量任务。

### 7.2 核心指标

| 阶段 | 指标 | MVP 目标值 | 说明 |
|---|---|---:|---|
| 激活 | 新用户 24 小时内完成首个任务 | ≥ 60% | 从注册到第一次感知价值 |
| 激活 | 新用户 24 小时内创建/导入课程并建立 3 个任务 | ≥ 35% | 作为深度激活指标，不阻断首次使用 |
| 导航 | 可用性测试首次点击正确率 | ≥ 80% | 找未来任务、收集箱任务、周反馈等指定目标 |
| 创建 | 快速记录中位耗时 | ≤ 10 秒 | 从点击“＋”到保存成功 |
| 决策 | 从打开“今天”到点击一个行动的中位耗时 | ≤ 5 秒 | 行动包含开始、完成、改期 |
| 提醒 | 提醒到达后 30 分钟内处理率 | ≥ 45% | 完成、稍后或改期均算处理 |
| 执行 | 本周到期任务按期完成率 | 较首周提升 10% | 同一用户前后对比更有意义 |
| 留存 | 第二周仍有有效执行行为的用户比例 | ≥ 30% | 早期小样本目标 |
| 导入 | 课表导入后需要人工修正的字段比例 | ≤ 10% | 高于该值不进入默认入口 |

### 7.3 护栏指标

- 通知权限关闭率不高于 25%。
- 用户主动关闭某类提醒的比例不高于 20%。
- 冲突提示被用户判定为误报的比例不高于 10%。
- 课表导入放弃率不高于 30%。
- 任务积压超过 20 条且 7 天无处理的用户比例持续下降。
- 不因版本升级导致已有任务丢失。

## 8. 信息架构

### 8.1 信息架构原则

一级导航只放稳定、高频、具有独立用户心智的空间，不直接映射每个产品功能。

- “提醒”是任务和日程的触达方式，不是一个独立目的地。
- “收集箱”是任务的一种状态，不是与任务并列的产品模块。
- “反馈”贯穿执行过程，并在今天和我的页面集中呈现，不需要单独占据高频导航。
- “＋”是全局动作，不是内容页面；点击后打开快速记录浮层。
- 课程、活动和任务在今天/日程统一呈现，但依然保持不同的数据和视觉语义。

### 8.2 目标主导航

```text
今天 ｜ 日程 ｜ ＋ ｜ 任务 ｜ 我的
```

| 入口 | 用户心智 | 产品职责 | 进入频率 | 不承担的职责 |
|---|---|---|---:|---|
| 今天 | 我现在该做什么 | 当前/下一项、逾期、今日计划、即时进度 | 每日多次 | 不展示全部任务和长期设置 |
| 日程 | 我的时间被什么占用 | 课程、活动、考试、已安排任务的时间视图 | 每日/每周 | 不承载无日期任务 |
| ＋ | 我先记下一件事 | 快速记录、渐进补充课程/时间/提醒 | 高频 | 不强迫填写完整表单 |
| 任务 | 我有哪些事情要处理 | 进行中、收集箱、即将到期、已完成、搜索筛选 | 每日 | 不重复今天页的执行排序 |
| 我的 | 我的进度和偏好 | 周反馈、学期、提醒、数据、账户 | 每周/低频 | 不放高频任务动作 |

#### 为什么不再让“收集箱”占一级导航

收集箱只解决“还没有规划时间的任务”，无法承接用户查看全部进行中、未来和已完成任务的需求。把它升级为一级入口会造成两个问题：

1. 用户无法明确去哪里找一项已经设置日期但不在今天的任务。
2. “任务”概念被拆成今天、日程和收集箱多个入口，继续制造入口分散。

因此，目标方案使用“任务”作为一级入口，在任务页内提供“进行中｜收集箱｜已完成”等二级筛选。

#### 为什么“反馈”不占一级导航

反馈是核心能力，但查看频率低于执行和任务管理。产品应在用户完成任务的当下给出即时反馈，在今天页展示今日反馈，在我的页展示周反馈入口。这样反馈进入闭环，而不是成为一个需要用户主动想起才访问的孤立页面。

### 8.3 导航行为规则

| 编号 | 优先级 | 规则 |
|---|---|---|
| NAV-01 | P0 | 底部栏固定为 5 个位置，4 个目的地 + 中央创建动作 |
| NAV-02 | P0 | 图标与文字标签同时存在，当前页面需有颜色、字重或形状状态，不只依赖颜色 |
| NAV-03 | P0 | 切换一级导航保留各页面滚动位置、筛选和搜索状态，不使用会重置状态的跳转方式 |
| NAV-04 | P0 | 任务详情、课程编辑、导入确认等二级页面使用明确返回按钮，返回后恢复来源页面状态 |
| NAV-05 | P0 | 通知点击可以深链到对应任务/日程，关闭详情后回到合理来源 |
| NAV-06 | P0 | “任务”入口可显示未规划任务数量徽标；徽标表示待处理状态，不用于制造焦虑 |
| NAV-07 | P0 | 中央“＋”点击后打开快速创建底部浮层，不先跳转到完整表单页 |
| NAV-08 | P0 | 底部栏避开系统手势区，所有触控区域满足移动端最小尺寸 |

### 8.4 核心产品路径

#### A. 首次使用路径

```text
打开应用
 → 直接体验 / 稍后登录
 → 用一句话记录第一件事
 → 保存成功，进入今天或“任务 > 收集箱”
 → 用户首次设置提醒时，再解释并申请通知权限
 → 完成第一项任务，获得即时反馈
 → 在第二次或第三次使用时提示建立/导入课表
 → 用户需要同步或换设备时再引导正式登录
```

设计原则：首次使用先让用户感受到“记录成功”和“下一步清楚”，不把注册、通知授权、课表导入同时堆在首次启动流程中。

#### B. 每日执行路径

```text
打开今天
 → 看当前/下一项
 → 处理需要关注的逾期或临近截止任务
 → 开始 / 完成 / 稍后 / 改期
 → 查看即时进度
 → 当天结束时查看今日小结
```

#### C. 捕获与整理路径

```text
任意页面点击“＋”
 → 输入标题并保存
 → 无时间：进入 任务 > 收集箱
 → 有截止/计划时间：进入对应日程与任务列表
 → 用户在空档集中整理收集箱
```

#### D. 提醒处理路径

```text
提醒到达
 → 直接完成 / 稍后 / 打开任务
 → 改期时检测冲突
 → 更新任务和后续提醒
 → 返回今天执行队列
```

#### E. 周反馈路径

```text
今天页周末反馈卡 / 我的页进度入口
 → 查看按期完成、改期和负荷高峰
 → 选择一条建议
 → 调整下周任务或默认计划偏好
```

### 8.5 一级与二级页面地图

```text
今天
├─ 当前/下一项
├─ 需要关注
├─ 今日计划
├─ 今日完成
└─ 今日/周反馈入口

日程
├─ 周视图 / 日视图
├─ 课程与固定活动
├─ 已安排任务
├─ 课程详情
└─ 课表导入与校对

＋ 快速记录浮层
└─ 更多设置 → 完整任务编辑

任务
├─ 进行中
├─ 收集箱
├─ 即将到期
├─ 已完成
├─ 搜索与筛选
└─ 任务详情

我的
├─ 本周进度
├─ 学期与作息
├─ 提醒设置
├─ 数据与同步
└─ 账户与隐私
```

### 8.6 实体关系

```text
学期 Term
 └─ 课程 Course
     ├─ 固定课节 CalendarEvent
     └─ 作业/复习任务 Task

社团/个人活动 CalendarEvent
 └─ 可关联准备任务 Task

```

## 9. 版本范围与优先级

| 能力 | P0：闭环 MVP | P1：增强版 | P2：规模化 |
|---|---|---|---|
| 快速创建 | 标题快速保存、收集箱、完整编辑 | 分享到应用、剪贴板识别 | AI 提取任务字段 |
| 课程与日程 | 手动课程、周期课节、CSV/ICS 模板导入 | 课表截图 OCR + 校对 | 指定高校教务系统适配 |
| 提醒 | 任务绑定、预设提醒、完成/改期同步 | 通知快捷操作、智能提醒建议 | 多设备推送一致性 |
| 执行 | 今天队列、完成、稍后、改期 | 开始任务、轻量计时 | 个性化执行节奏建议 |
| 反馈 | 即时反馈、今日总结、本周按期完成率 | 课程维度趋势、负荷分布 | 个性化学习激励模型 |
| 冲突 | 固定时间重叠、任务计划时间重叠 | 日负荷超载提示、建议空档 | 自动重排多个任务 |
| 数据 | 本地数据版本、迁移、导出 | 云端账号与同步 | 多端实时协同 |

P0 完成前不得优先建设 P2 能力。

## 10. 详细功能需求

### 10.1 首次使用与渐进激活

#### 目标

让新用户先完成一次真实的记录和执行，再逐步理解账号、通知和课表能力。

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| ONB-01 | P0 | 首次打开允许直接体验，不以注册作为感知核心价值的前置条件 |
| ONB-02 | P0 | 首次路径只要求用户记录一件真实任务，完成后进入今天或任务中心 |
| ONB-03 | P0 | 用户首次创建提醒时再申请通知权限，并在申请前解释用途 |
| ONB-04 | P0 | 用户完成首个任务后展示即时反馈，并提示下一步可以建立课表或继续记录 |
| ONB-05 | P0 | 正式登录在用户需要同步、换设备或恢复数据时触发 |
| ONB-06 | P0 | 所有引导均可跳过，跳过后核心任务管理仍可使用 |
| ONB-07 | P1 | 根据用户是否已有课程和任务，动态选择课表引导时机 |

#### 验收标准

- 新用户无需先完成多页介绍、通知授权和课表导入即可创建首个任务。
- 通知权限拒绝不影响任务保存。
- 跳过课表引导后可以从日程空状态和更多菜单再次进入。
- 本地体验用户的任务在后续注册时能够安全合并，不生成重复数据。

### 10.2 全局快速创建

#### 目标

降低任务记录成本，使用户不需要先决定课程、日期和提醒也能保存信息。

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| CAP-01 | P0 | 主导航中央“＋”在今天、日程、任务、我的页面始终可见 |
| CAP-02 | P0 | 点击后打开快速创建底部浮层，标题自动聚焦 |
| CAP-03 | P0 | 标题为唯一必填项，长度 1–80 字符 |
| CAP-04 | P0 | 不填写日期时保存至收集箱 |
| CAP-05 | P0 | 可选填写课程/分类、截止时间、计划时间、预计耗时、描述、提醒 |
| CAP-06 | P0 | 浮层默认只展示标题、课程、日期和保存；“更多设置”再展开完整字段 |
| CAP-07 | P0 | 保存成功后关闭浮层、保留来源页面状态，并提供“撤销/查看”反馈 |
| CAP-08 | P0 | 有未保存输入时关闭浮层，需要确认放弃或自动保存草稿 |
| CAP-09 | P0 | 保存期间禁用重复提交，并显示明确进行中状态 |
| CAP-10 | P1 | 支持通过系统分享菜单将选中文本发送到 TaskManage |

#### 业务规则

- 标题去除首尾空格后不能为空。
- 快速创建默认状态为 `todo`。
- 快速创建默认不设置截止日期，避免错误地将任务全部堆到当天。
- 如果选择课程，任务继承课程颜色，但用户可单独修改分类。
- 如果同时填写计划时间和预计耗时，系统即时执行冲突检测。
- 保存失败时保留全部输入，不清空表单。
- 快速创建浮层不是完整任务详情；复杂字段通过“更多设置”渐进展开。
- 浮层打开和关闭不重置底层页面的滚动位置和筛选状态。

#### 验收标准

- 从任一主页面点击“＋”均能打开同一个快速创建流程。
- 只填标题可以成功保存并在收集箱出现。
- 添加截止日期后，任务不再出现在收集箱，并进入对应日期的日程/今天视图。
- 重复点击保存不会生成重复任务。
- 放弃含有输入的浮层不会静默丢失内容。

### 10.3 任务中心与收集箱

#### 目标

为用户提供一个稳定的“全部任务”入口，承接进行中、未规划和已完成任务；收集箱作为任务中心内的二级状态，继续支持“先记录、后规划”。

#### 页面结构

任务页顶部提供搜索、筛选和以下二级标签：

```text
进行中 ｜ 收集箱（数量） ｜ 即将到期 ｜ 已完成
```

- **进行中**：全部 `todo/doing` 任务，按需要关注程度排序。
- **收集箱**：没有截止时间和计划时间的未完成任务。
- **即将到期**：未来 7 天内到期的未完成任务。
- **已完成**：按完成时间倒序，默认只加载最近 30 天。

#### 展示范围

满足以下条件的任务进入收集箱：

```text
status ∈ {todo, doing}
AND scheduledStartAt 为空
AND dueAt 为空
```

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| TSKC-01 | P0 | 主导航“任务”进入任务中心，默认展示进行中 |
| TSKC-02 | P0 | 支持按标题搜索，并按课程、类型、状态、日期筛选 |
| TSKC-03 | P0 | 标签切换后保留筛选、滚动位置和上次选择 |
| INB-01 | P0 | 收集箱标签展示未规划任务数量和按创建时间倒序的任务列表 |
| INB-02 | P0 | 点击任务进入详情编辑 |
| INB-03 | P0 | 支持快速安排“今天、明天、本周、自定义” |
| INB-04 | P0 | 支持关联课程/活动 |
| INB-05 | P0 | 支持完成、删除和批量规划 |
| INB-06 | P1 | 当收集箱超过 10 条或最旧任务超过 7 天时提示整理 |
| TSKC-04 | P1 | 支持保存常用筛选，但不在 P0 增加自定义复杂视图 |

#### 验收标准

- 任务补充截止时间或计划时间后立即离开收集箱。
- 已完成或已取消任务不出现在收集箱。
- 用户能从任务页找到未来、未规划和已完成任务，不需要在多个一级页面猜测位置。
- 各标签空状态提供与该状态有关的下一步操作，不展示无意义统计。

### 10.4 课程、固定活动与日程

#### 目标

建立课程和活动的固定时间底座，让任务有上下文，并为冲突判断提供可靠数据。

#### 实体定义

- **课程 Course**：课程名称、教师、地点、颜色、所属学期等元数据。
- **固定日程 CalendarEvent**：某次课、社团活动、考试或会议，包含开始和结束时间。
- **任务 Task**：需要用户完成的行动，例如提交作业、复习、准备材料。

课程本身不是任务；一次课是固定日程；课程作业是关联课程的任务。

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| SCH-01 | P0 | 日程页支持日/周视图切换，默认周视图 |
| SCH-02 | P0 | 课程和固定活动以时间块展示，任务以截止标记或计划时间块展示 |
| SCH-03 | P0 | 支持手动创建课程，并设置学期、周几、节次/时间、起止周、单双周、地点 |
| SCH-04 | P0 | 支持重复规则和单次调课、停课例外 |
| SCH-05 | P0 | 支持 CSV/ICS 标准模板导入 |
| SCH-06 | P0 | 导入前进入确认页，用户可修改错误字段后提交 |
| SCH-07 | P0 | 导入时进行去重，不默认覆盖已有课程 |
| SCH-08 | P1 | 支持课表截图 OCR 识别，识别结果必须人工确认 |
| SCH-09 | P2 | 针对用户集中的高校适配教务系统 |

#### 导入分层方案

##### A. P0：模板/日历导入

支持：

- 产品提供的 CSV 模板。
- 标准 ICS 日历文件。
- 手动批量复制一周课程。

优势：数据结构清晰、开发成本可控、准确率可验证。

##### B. P1：截图 OCR

流程：

```text
选择课表截图
 → 本地/服务端 OCR
 → 识别课程名、星期、节次、地点
 → 根据学校作息表映射实际时间
 → 进入网格校对页
 → 用户确认
 → 创建课程和周期日程
```

必须记录：识别置信度、用户修改字段、失败原因。低置信度字段必须高亮，不能静默导入。

##### C. P2：教务系统适配

只在目标用户明显集中于少数高校、且学校允许合规接入时开发。不得要求用户将教务密码明文提交给 TaskManage。

#### 验收标准

- 用户可以建立至少一门每周重复课程。
- 导入前后课程数量、日期和重复规则一致。
- 同一导入文件重复导入不会生成完全重复的课程。
- 修改或删除周期课程时，用户可选择“仅本次”或“全部重复日程”。

### 10.5 任务详情与生命周期

#### 字段

| 字段 | P0 | 说明 |
|---|---:|---|
| 标题 | 必填 | 1–80 字符 |
| 描述 | 可选 | 最多 500 字符，首版纯文本 |
| 类型 | 必填 | 作业、复习、社团、个人、其他 |
| 课程/活动归属 | 可选 | 关联 Course 或 CalendarEvent |
| 截止时间 `dueAt` | 可选 | 表示最晚完成时间 |
| 计划开始时间 `scheduledStartAt` | 可选 | 表示用户打算何时执行 |
| 预计耗时 | 可选 | 5–480 分钟 |
| 优先级 | 可选 | 高、普通、低，默认普通 |
| 状态 | 必填 | todo、doing、done、cancelled |
| 提醒 | 可选 | 可设置多个，但首版界面默认最多展示 2 个 |

#### 状态流转

```text
todo ──开始──> doing ──完成──> done
  │                │
  ├────完成────────┘
  └────取消────────────> cancelled

done ──撤销完成──> todo
cancelled ──恢复──> todo
```

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| TSK-01 | P0 | 新增、编辑、完成、恢复、取消、删除任务 |
| TSK-02 | P0 | 任务详情展示课程、截止时间、计划时间、预计耗时和提醒 |
| TSK-03 | P0 | 改期时同步重算提醒和冲突 |
| TSK-04 | P0 | 完成时取消所有未触发提醒并记录完成时间 |
| TSK-05 | P0 | 删除前二次确认，并同步取消提醒 |
| TSK-06 | P0 | 允许用户将任务重新放回收集箱 |
| TSK-07 | P1 | 支持周期任务，但不得与周期课程共用同一编辑逻辑 |

#### 截止时间与计划时间区别

- “周五 23:59 前提交论文”是截止时间。
- “周四 19:00–20:30 写论文”是计划时间。
- 一个任务可以只有截止时间，也可以同时有计划时间和截止时间。
- 冲突检测针对计划时间段；负荷提示结合截止时间和预计耗时。

### 10.6 今天：执行中心

#### 目标

用户打开产品后，无需浏览全部任务即可知道当前和下一步应该做什么。

#### 内容结构与排序

按以下顺序展示：

1. 正在进行或 30 分钟内开始的课程/活动。
2. 已逾期且未完成的任务。
3. 今天已安排执行时间的任务，按计划开始时间排序。
4. 今天截止但未安排执行时间的任务，按截止时间和优先级排序。
5. 下一项固定日程。
6. 今日已完成折叠区。
7. 收集箱未整理数量提示。

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| TOD-01 | P0 | 只展示与今天执行有关的内容，不再默认展示全部历史任务 |
| TOD-02 | P0 | 顶部显示当前日期、今日已完成/应完成数量和下一项安排 |
| TOD-03 | P0 | 每个任务支持完成、开始、稍后、改期 |
| TOD-04 | P0 | 逾期任务必须给出“重新安排”动作，不能只显示红色 |
| TOD-05 | P0 | 固定日程与任务使用不同视觉语义，并可显示课程颜色 |
| TOD-06 | P1 | 根据用户空档和预计耗时推荐可安排时间 |

#### 空状态

- 今天没有任务但有课程：显示下一节课和“添加课后任务”。
- 今天没有任何安排：显示轻量鼓励和“快速记录”。
- 有大量逾期任务：优先引导重新规划，不显示庆祝型空状态。

#### 验收标准

- 未来日期任务不应无条件出现在今天主队列。
- 逾期任务、今日截止任务、今日计划任务分类准确。
- 完成任务后数据、提醒和今日进度即时更新。

---

### 10.7 统一提醒

#### 目标

将提醒变成任务的一部分，使提醒触发、完成、改期和删除始终一致。

#### 提醒类型

| 类型 | 示例 | 默认策略 |
|---|---|---|
| 截止前提醒 | 截止前 1 天、2 小时 | 作业默认截止前 1 天 + 2 小时 |
| 计划开始提醒 | 计划开始时、提前 10 分钟 | 用户设置计划时间后默认提前 10 分钟 |
| 固定日程提醒 | 上课前 10 分钟 | 课程默认提前 10 分钟 |
| 稍后提醒 | 15 分钟、1 小时、今晚、自定义 | 从通知或任务卡片触发 |

默认提醒策略必须允许用户在“我的”中关闭或修改。

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| REM-01 | P0 | Reminder 必须关联 `taskId` 或 `eventId`，禁止孤立提醒 |
| REM-02 | P0 | 新建任务时可选择预设提醒或自定义时间 |
| REM-03 | P0 | 任务完成/取消/删除时取消未触发提醒 |
| REM-04 | P0 | 任务改期时重新计算相对提醒；绝对提醒需询问是否同步 |
| REM-05 | P0 | 通知点击进入对应任务详情 |
| REM-06 | P0 | 提醒列表作为任务详情和设置能力，不重新占用主导航 |
| REM-07 | P1 | 通知支持“完成、稍后、改期”快捷操作 |
| REM-08 | P1 | 支持免打扰时段，免打扰期间提醒顺延或静默进入通知中心 |

#### 权限流程

1. 首次创建提醒时再申请通知权限，不在首次启动时索取。
2. 申请前解释用途：“用于在作业截止和计划开始前提醒你”。
3. 用户拒绝后，任务仍可保存，并在详情显示“系统通知未开启”。
4. 再次开启需引导用户进入系统设置，不循环弹窗。

#### 可靠性要求

- Android、iOS 必须分别测试前台、后台、应用被结束、设备重启、时区变化场景。
- 原生适配器必须返回可取消的系统通知标识。
- 所有提醒调度操作必须有本地状态：scheduled、delivered、cancelled、failed。
- 调度失败不能静默，应在任务详情和埋点中可见。

### 10.8 执行动作

#### 目标

让用户在看到任务或提醒后立即做出决策，不把所有未完成任务永久堆积。

#### 动作定义

| 动作 | 结果 |
|---|---|
| 开始 | 状态变为 doing，记录 `startedAt` |
| 完成 | 状态变为 done，记录 `completedAt`，取消未触发提醒 |
| 稍后 | 不改变截止时间，只创建新的短期提醒 |
| 改期 | 修改计划时间或截止时间，重新检测冲突并调整提醒 |
| 取消 | 状态变为 cancelled，不进入完成率分母 |

#### 规则

- “稍后”不能无限自动重复。连续稍后 3 次后，系统提示用户重新安排时间。
- 改期不等于失败。周反馈单独统计改期次数，但不使用负面惩罚文案。
- doing 状态超过 24 小时仍未完成时，在今天页提示确认状态。
- MVP 不强制启动计时器；开始动作仅用于表达执行状态。

---

### 10.9 进度与学习激励反馈

#### 目标

通过真实、可解释的执行数据，让用户知道自己完成了什么、计划是否合理、下一周如何调整。

#### 反馈层级

##### A. 即时反馈（P0）

- 完成任务后显示轻量勾选动画和具体文案，例如“高数作业已完成”。
- 同时更新今天进度，不弹出阻断式全屏庆祝。
- 撤销完成入口至少保留 5 秒。

##### B. 今日反馈（P0）

展示：

- 今日应处理任务数。
- 已完成数。
- 按期完成数。
- 合理改期数。
- 仍逾期数。

##### C. 周反馈（P0）

展示：

- 本周计划任务数。
- 按期完成率。
- 完成任务总数。
- 改期次数。
- 按课程/类型分布。
- 负荷最高的日期。
- 一条可执行建议，例如“周三安排了 6 小时任务，可尝试提前分散”。

#### 指标口径

```text
按期完成率 = completedAt <= dueAt 的已完成到期任务数
             ÷ 本周已到期且未取消任务数
```

- 没有截止时间的收集箱任务不进入按期完成率。
- 取消任务不进入分母。
- 本周尚未到期的未来任务不进入分母。
- 历史总完成率可保留在详情，但不得作为首页主要激励指标。

#### 激励原则

- 表扬具体行为，如“你按计划完成了 4 项任务”。
- 不使用“断签”“失败”“落后于他人”等文案。
- 不设置社交排行榜。
- 连续执行可以作为自我趋势展示，但关闭后不影响其他功能。

### 10.10 时间冲突与负荷提示

#### 冲突类型

| 类型 | 定义 | 示例 | 提示级别 |
|---|---|---|---|
| 固定日程硬冲突 | 两个 CalendarEvent 时间段重叠 | 上课与社团会议重叠 | 高 |
| 计划任务硬冲突 | 任务计划时间与课程/活动/另一任务重叠 | 计划复习时正在上课 | 高 |
| 时间逻辑错误 | 开始时间晚于结束/截止时间 | 20:00 开始，19:00 截止 | 阻断保存 |
| 截止风险 | 剩余可用时间小于预计耗时 | 1 小时后截止，但预计 2 小时 | 中 |
| 日负荷过高 | 当日任务预计耗时超过可用空档或用户阈值 | 空档 3 小时，安排 6 小时 | 中 |

#### 功能要求

| 编号 | 优先级 | 需求 |
|---|---|---|
| CON-01 | P0 | 新建/编辑课程、活动和有计划时间的任务时检测重叠 |
| CON-02 | P0 | 导入课表确认页集中展示冲突 |
| CON-03 | P0 | 冲突提示必须说明与哪个事项、哪段时间冲突 |
| CON-04 | P0 | 除时间逻辑错误外，允许用户确认后继续保存 |
| CON-05 | P1 | 根据空档推荐 1–3 个可选时间 |
| CON-06 | P1 | 根据预计耗时和截止时间提示日负荷风险 |

#### 重叠判断

两个时间段 `[startA, endA)` 与 `[startB, endB)` 在以下条件下冲突：

```text
startA < endB AND startB < endA
```

结束时间恰好等于另一事项开始时间不算冲突。

## 11. 核心流程

### 11.1 快速记录流程

```text
任一主页面点击“＋”
 → 输入标题
 → 可选补充课程/日期/提醒
 → 保存
 → 无日期：进入“任务 > 收集箱”
 → 有日期：进入日程，并在适用日期进入今天
```

异常处理：

- 标题为空：在标题字段下显示错误并保持焦点。
- 本地写入失败：保留表单，提示重试。
- 通知权限被拒：任务保存成功，仅提醒状态显示未启用。

### 11.2 收集箱规划流程

```text
进入“任务 > 收集箱”
 → 选择任务
 → 选择“今天 / 明天 / 本周 / 自定义”
 → 可选关联课程和预计耗时
 → 运行冲突检测
 → 保存
 → 从收集箱移除
```

### 11.3 课表导入流程

```text
日程页选择“导入课表”
 → 选择 CSV / ICS / 截图（P1）
 → 解析
 → 展示课程网格和错误字段
 → 检测重复与冲突
 → 用户修正并确认
 → 批量创建课程与固定日程
 → 展示导入结果：成功、跳过、失败数量
```

### 11.4 提醒处理流程

```text
提醒触发
 → 用户点击通知
 → 进入任务详情
 → 完成：更新状态并取消剩余提醒
 → 稍后：创建新的短期提醒
 → 改期：选择时间、检测冲突、重排提醒
```

### 11.5 完成与反馈流程

```text
用户完成任务
 → 记录 completedAt
 → 取消未触发提醒
 → 更新今天进度
 → 展示轻量完成反馈 + 撤销
 → 写入周反馈统计
```

## 12. 产品体验与页面设计方案

### 12.1 当前页面体验诊断

当前页面已经建立统一的浅色视觉风格，但产品路径和内容层级仍存在以下问题：

| 当前问题 | 用户影响 | 目标调整 |
|---|---|---|
| 业务页面顶部使用较大的英文宣传式标题 | 首屏空间被品牌文案占用，真正的任务信息下沉 | 使用紧凑中文页面标题，把当前/下一项放到首屏 |
| 今天页展示全部未完成任务和全部已完成任务 | 用户无法判断什么是“今天必须处理” | 按当前、逾期、今日计划、今日截止排序 |
| 首页历史总完成率圆环占据视觉中心 | 指标失真，且不能指导下一步 | 改为“今日完成 2/4”和下一项行动 |
| 收集箱独占一级导航 | 用户找不到全部进行中和未来任务 | 一级入口改为任务，收集箱作为二级标签 |
| 日程页只是截止日期分组列表 | 与任务列表差异弱，无法表达课程时间 | 改为真实时间轴/周课表，固定日程和任务使用不同样式 |
| 创建任务首先进入完整页面 | 记录过程仍偏重 | 中央“＋”先打开快速创建浮层，复杂字段渐进展开 |
| 我的页以历史任务数字为主 | 与学习反馈定位关联不足 | 第一屏展示本周反馈，再展示设置和账户 |
| 页面之间通过重置式跳转切换 | 滚动位置、筛选和返回路径可能丢失 | 一级导航保存状态，二级页面使用可预测返回 |
| 中英文业务文案混用 | 产品显得像技术原型 | 中文作为默认产品语言，英文仅用于必要缩写 |

### 12.2 目标体验方向

整体采用**内容优先、克制、清晰的轻量效率工具风格**，视觉上延续当前低饱和绿和暖白基调，但不让装饰性卡片、巨大标题和动效盖过任务内容。

设计关键词：

```text
安静 / 清楚 / 可信 / 轻量 / 有节奏 / 不制造压力
```

#### 页面层级

每个一级页面遵循同一结构：

```text
系统安全区
紧凑顶部栏：页面标题 + 1 个必要辅助动作
首要内容：用户最需要做的判断
次要内容：列表、趋势、设置
底部安全留白
全局底部导航
```

#### 视觉原则

- 页面标题使用中文、单行、内容型表达，如“今天”“日程”“任务”，不再使用大幅宣传口号。
- 一个屏幕只设置一个主操作；其他操作使用次级按钮、文字按钮或更多菜单。
- 列表是主要内容表达，卡片只用于“当前/下一项、冲突、反馈”等需要分组强调的内容。
- 课程颜色只表达课程归属，不同时承担状态、优先级和错误含义。
- 成功、警告、逾期同时使用颜色、图标和文字，避免只靠红绿区分。
- 默认使用系统中文字体，减少额外字体加载和多端差异。
- 动效只用于浮层进入、任务完成和状态变化；必须支持减少动态效果。

### 12.3 主导航设计

#### 结构线框

```text
┌──────────────────────────────────────┐
│               页面内容               │
│                                      │
├──────────────────────────────────────┤
│  今天    日程      ＋      任务    我的 │
│  ●当前                     3          │
└──────────────────────────────────────┘
```

#### 设计要求

- 4 个一级页面等宽排列，中央“＋”略高于导航栏但不能遮挡内容。
- “＋”的完整按钮触控范围至少满足平台标准，不以视觉圆形大小代替触控范围。
- 每个导航项同时展示统一线性图标与文字标签。
- 当前项至少同时使用两种状态表达，例如主色 + 字重/顶部指示线。
- “任务”可显示未规划数量，最大显示 `9+`；没有待规划任务时不显示徽标。
- 导航栏高度、底部安全区和页面底部内边距由统一设计变量控制。
- 一级页面切换不产生层层返回栈；二级页面保留明确返回路径。

### 12.4 首次使用与激活

#### 目标

先让用户完成第一项真实任务，再逐步引导通知、课表和账号，避免复杂 onboarding 造成流失。

#### 页面与路径

```text
┌──────────────────────────────┐
│ TaskManage                   │
│ 今天先记住一件事             │
│                              │
│ [ 输入课程、作业或活动 ]      │
│                              │
│ [开始使用]                   │
│ 稍后再登录                   │
└──────────────────────────────┘
```

- 首屏只解释核心价值和提供一个标题输入框。
- 允许“直接体验”，本地创建匿名用户空间。
- 用户第一次添加提醒时申请通知权限。
- 用户创建 2–3 个任务后，在合适位置提示“建立课表后可自动发现时间冲突”。
- 用户开启同步、换设备或需要数据恢复时再引导正式注册。
- 如果业务决定正式账号必须前置，登录页仍需提供密码管理器、粘贴和清晰的返回/退出路径。

### 12.5 今天页

#### 页面目标

回答三个问题：我现在在做什么？下一项是什么？今天还有什么必须处理？

#### 结构线框

```text

│ 11:00  提交英语阅读作业      [完成]  │
│                                      │

│ ! 数据结构作业 · 已逾期       [改期] │
│                                      │

```

#### 内容与交互

- 顶部只保留日期、头像/设置入口和今日完成进度，不显示历史总完成率。
- “现在”卡只在当前存在课程、活动或正在进行任务时显示。
- “下一项”只显示一个最相关事项，提供一个与其状态匹配的主动作。
- “需要关注”包含逾期、提醒失败、时间冲突和临近截止但尚未安排的任务。
- “今日计划”使用可扫描列表，固定日程与任务通过图标、时间格式和标签区分。
- 完成动作支持撤销；改期打开时间选择浮层，不跳转多个页面。
- 已完成默认折叠，避免首屏被历史内容占用。
- 今日没有安排时，展示“今天暂无安排”和快速记录，不显示虚假庆祝。

#### 首页禁止项

- 不展示全部未来任务。
- 不展示全部历史已完成任务。
- 不以大面积营销文案替代执行信息。
- 不同时出现多个视觉权重相同的主按钮。

#### 内容与交互

- 日/周切换是同一页面内的视图切换，保留选中日期。
- 固定课程/活动使用实心时间块；可移动任务使用边框或虚线时间块，并附类型文字。
- 未安排时间但当天截止的任务显示在当天顶部“截止事项”，不伪装成时间块。
- 点击时间块打开详情；点击空档可预填该时间创建任务/活动。
- 导入课表入口放在右上角更多菜单和空状态主按钮中，不常驻为高权重 CTA。
- 有冲突时在对应时间块和页面顶部摘要中同时提示。
- 首版周视图不支持复杂拖拽；所有拖拽必须同时提供点击编辑替代操作。

#### 结构线框

#### 内容与交互

- 打开后标题立即获得焦点，键盘不遮挡保存按钮。
- 默认仅展示标题和 3 个高频快捷字段：课程、日期、提醒。
- “更多设置”展开描述、计划时间、预计耗时、类型和优先级。
- 保存是唯一主按钮；关闭是图标按钮并具有可访问名称。
- 无日期保存后进入任务页的收集箱标签。
- 浮层关闭后回到原页面、原滚动位置。
- 输入内容后关闭需要确认，或自动保存草稿并明确提示。

### 12.11 周反馈页

#### 页面目标

帮助用户调整计划，而不是只展示漂亮图表。

#### 页面结构

1. 本周一句话总结，例如“你按期完成了 8/10 项任务”。
2. 按期完成率和上周对比。
3. 每日完成数量趋势；图表同时提供文字摘要。
4. 课程/类型分布，类别超过 5 个时使用条形图而非饼图。
5. 改期次数与负荷最高日期。
6. 一条可以执行的下周建议。
7. “规划下周”主按钮。

数据不足时不显示空坐标轴，改为说明“完成 3 个有截止时间的任务后，这里会生成按期趋势”。

### 12.12 课表导入与校对页

#### 页面目标

让用户在批量写入前明确知道系统识别了什么、哪里有风险。

#### 页面结构

```text
选择来源
 → 解析进度
 → 周课表网格预览
 → 错误/低置信度字段清单
 → 重复项与冲突摘要
 → 确认导入
 → 结果页：成功 / 跳过 / 失败
```

- 多步骤流程显示当前步骤和总步骤，并允许返回修改。
- 低置信度字段同时使用警告图标、文字和颜色。
- 默认不覆盖已有课程，重复项默认跳过。
- 确认按钮显示实际数量，例如“导入 12 节课”。
- 解析失败需要说明原因和恢复方式，例如重新选择文件或下载模板。
- 导入过程中离开页面需要保留草稿或二次确认。

### 12.13 页面状态矩阵

| 页面 | 加载状态 | 空状态 | 错误/权限状态 | 主要恢复动作 |
|---|---|---|---|---|
| 今天 | 首屏骨架，保留布局高度 | 无安排 + 快速记录 | 部分数据失败、离线 | 重试、继续使用本地数据 |
| 日程 | 时间轴骨架 | 建立/导入课表 | 导入失败、冲突 | 重试、手动创建、查看冲突 |
| 快速创建 | 保存按钮进行中 | 不适用 | 字段错误、写入失败 | 修改、重试，输入保留 |
| 任务 | 列表骨架 | 按当前标签给出下一步 | 搜索失败、离线 | 清除筛选、重试 |
| 任务详情 | 内容骨架 | 数据不存在 | 提醒失败、权限关闭 | 返回、重新调度、打开设置 |
| 周反馈 | 统计骨架 | 数据不足说明 | 统计失败 | 重试、查看任务明细 |
| 课表导入 | 明确步骤与进度 | 无有效课程 | 文件错误、低置信度、部分失败 | 修正、跳过、重新上传 |
| 我的 | 账户与设置骨架 | 不适用 | 未登录、同步失败 | 登录、重试、本地继续 |

### 12.14 视觉系统要求

| 类别 | 规范 |
|---|---|
| 风格 | 简洁、内容优先、低装饰；禁止为了“高级感”滥用透明卡片和模糊背景 |
| 色彩 | 使用语义变量：背景、表面、主文字、次文字、主操作、成功、警告、错误、课程色 |
| 字体 | 默认系统中文字体；正文不小于移动端可读标准；标题、正文、标签采用固定字阶 |
| 间距 | 使用 4/8pt 递增体系，一级页面保持一致水平边距 |
| 图标 | 使用同一套矢量线性图标；结构性图标不使用 Emoji 或字体符号拼接 |
| 卡片 | 只用于需要分组或强调的内容；普通任务列表使用分隔和留白即可 |
| 动效 | 完成反馈、浮层和状态变化使用短促、可中断动效；减少动态效果时直接呈现最终状态 |
| 深色模式 | 与浅色模式同时定义语义色，不采用简单颜色反转 |
| 数据图表 | 必须提供数值或文字摘要，不能只靠颜色和图形表达结果 |

### 12.15 通用交互要求

- 所有主要触控区域至少 44pt（iOS）/48dp（Android），相邻触控目标保留足够间距。
- 底部导航、固定操作区和键盘同时出现时，关键按钮不得被遮挡。
- 点击后 100ms 内提供视觉反馈；异步保存显示进行中并禁止重复提交。
- 颜色不能作为唯一状态表达，状态需同时有文字、图标或形状。
- 删除、清空、覆盖导入等不可逆操作必须二次确认；普通完成操作优先提供撤销。
- 所有列表必须覆盖加载、空、错误和离线状态。
- 表单使用可见标签；错误显示在对应字段附近，提交失败不得丢失输入。
- 返回操作必须恢复来源页面的滚动位置、筛选和搜索条件。
- 不依赖左滑、拖拽等手势完成关键动作，始终提供可见按钮替代。
- 支持系统大字体、屏幕阅读器、减少动态效果和横屏基本可用。
- 移动端设计基准至少覆盖 375px 小屏、大屏手机和平板；内容不能横向溢出。

## 14. 本地数据升级与兼容

### 14.1 数据版本

本地存储新增：

```text
schemaVersion: 2
```

应用启动时按版本顺序执行迁移，迁移前生成可恢复备份；迁移成功后再写入新版本号。

### 14.2 旧任务迁移

当前字段：

```text
id, title, description, dueDate, status, createdAt, updatedAt
```

迁移规则：

- `dueDate` 为空：`dueAt = null`，保留在收集箱。
- `dueDate` 有值：转换为用户本地时区当日 23:59 的 `dueAt`。
- `type = other`。
- `priority = normal`。
- `source = manual`。
- `completedAt` 无法从旧数据恢复；旧 done 任务标记为 `completionTimeUnknown = true`，不进入首周按期完成率。
- 原独立提醒不自动绑定任务；升级后进入“待确认提醒”清单，用户选择关联或删除，禁止根据标题静默匹配。

### 14.3 迁移验收

- 升级前后任务总数一致。
- 标题、描述、状态和日期不丢失。
- 迁移失败时恢复旧数据并提示用户重试。
- 迁移过程可重复执行且结果一致。

### 15.1 客户端

保留现有技术栈：

- uni-app + Vue 3。
- Pinia 管理页面状态和领域状态。
- Repository 层负责本地/远端数据切换。
- `src/native/` 负责通知等平台适配。

建议新增目录：

```text
src/
├─ data/
│  ├─ migrations/
│  ├─ courseRepository.js
│  ├─ eventRepository.js
│  ├─ reminderRepository.js
│  └─ statusLogRepository.js
├─ domain/
│  ├─ conflictService.js
│  ├─ feedbackService.js
│  └─ reminderService.js
├─ stores/
│  ├─ courses.js
│  ├─ calendar.js
│  └─ feedback.js
└─ pages/
   ├─ schedule/import.vue
   ├─ schedule/course-edit.vue
   ├─ tasks/detail.vue
   └─ feedback/weekly.vue
```

### 15.2 提醒实现

当前 `plus.push.createMessage` 只能作为技术验证。正式版需要选择并验证可调度、可取消、支持点击参数回传的本地通知方案。

必须封装统一接口：

```js
scheduleReminder(reminder)
cancelReminder(systemNotificationId)
rescheduleReminder(reminder)
checkNotificationPermission()
openNotificationSettings()
```

平台不支持的能力必须返回明确状态，不能假装成功。

### 15.3 服务端

封闭测试可继续本地优先；满足下列任一条件时引入服务端：

- 需要多设备同步。
- 需要 OCR 服务。
- 需要正式账号与数据恢复。
- 需要跨设备推送。

正式账号不得继续保存明文密码。可选择成熟身份服务或后端哈希认证，并提供数据导出和账号删除能力。

### 15.4 平台策略

- **Android/iOS App 优先**：统一提醒是核心价值，需要可靠的系统通知能力。
- **H5**：用于产品演示、数据查看和轻量录入，不承诺后台提醒等价。
- **微信小程序**：通知需遵守平台订阅消息限制，不能直接复用 App 提醒承诺。

## 17. 非功能需求

### 17.1 性能

- 本地快速创建保存反馈应在 400ms 内出现。
- 1000 条任务、500 个日程下，今天页首屏计算不超过 300ms。
- 日程周视图滚动保持流畅，不在渲染阶段重复进行全量冲突计算。

### 17.2 离线与一致性

- 创建、编辑、完成、改期在离线状态下可用。
- 本地写入成功是操作成功的最低条件。
- 引入云同步后使用 `updatedAt + version` 或等价机制处理冲突，不静默覆盖新数据。

### 17.3 可访问性

- 触控目标符合移动端尺寸要求。
- 文字对比度符合 WCAG AA。
- 图标按钮有可访问名称。
- 状态不只依赖颜色。
- 系统大字体下不遮挡主要操作。
- 减少动态效果开启时关闭非必要动画。

### 17.4 安全与隐私

- 正式发布前移除明文密码存储。
- 在 OCR 功能上线前移除无必要的相机权限；选择照片时仅申请相册所需权限。
- 课表截图处理后按隐私策略及时删除原图。
- 提供本地数据导出、清除和账号删除。
- 不在通知正文默认展示敏感描述，允许用户选择隐藏通知详情。

## 19. 研发迭代计划

以下估算基于：1 名熟悉 uni-app 的开发者全职，产品/设计和测试兼职配合；不包含高校教务系统深度适配。若同时建设正式后端或 OCR 服务，应另行估算。

### Sprint 0：定义与验证（3–5 个工作日）

- 确认任务与日程实体边界。
- 完成首次使用、主导航、今天、日程、快速创建、任务中心、任务详情、我的和课表导入确认页交互稿。
- 用可点击原型测试 5–10 名学生。
- 冻结 P0 范围和埋点口径。

退出条件：80% 测试用户不经提示即可找到正确入口，并独立完成快速记录、规划、提醒处理和完成闭环。

### Sprint 1：数据模型与迁移（1 周）

- 引入 schemaVersion 和备份恢复。
- 扩展 Task 字段。
- 新增 Course、CalendarEvent、Reminder、StatusLog。
- 完成旧任务和独立提醒迁移测试。

退出条件：现有任务零丢失；迁移可重复执行。

### Sprint 2：导航、创建、任务中心与今天（1.5–2 周）

- 将目标主导航落地为今天｜日程｜＋｜任务｜我的，并保存页面状态。
- 将全局创建改为快速浮层，完善渐进字段和草稿保护。
- 建设任务中心及进行中、收集箱、即将到期、已完成标签。
- 收集箱快速规划。
- 重构今天队列及排序。
- 完成、开始、稍后、改期动作。

退出条件：完整创建—规划—执行流程可离线运行。

### Sprint 3：统一提醒（1.5–2 周）

- 选择并封装正式本地通知方案。
- 绑定任务/日程。
- 完成改期、删除、完成同步。
- Android/iOS 设备矩阵测试。

退出条件：提醒创建、触发、取消和改期通过核心设备测试。

### Sprint 4：课程与课表（1.5–2 周）

- 课程和周期日程。
- 周日程视图。
- CSV/ICS 导入及确认页。
- 重复检测和调课例外。

退出条件：一份标准课表可完整导入、校对和展示。

### Sprint 5：冲突、反馈与埋点（1–1.5 周）

- 时间重叠检测。
- 今日和周反馈。
- 核心事件埋点。
- 权限、错误和空状态补齐。

退出条件：所有 P0 UAT 场景通过，数据口径可验证。

### Sprint 6：封闭测试与修复（1–2 周）

- 20–30 名学生连续使用两周。
- 分析提醒处理率、逾期率、任务积压和课表修正率。
- 修复数据、提醒和迁移问题。
- 决定是否进入 OCR 课表识别。

预计：P0 可测试版本约 8–10 周。提醒插件选择、原生设备问题、页面交互重构和数据迁移可能影响周期。

## 22. 发布门槛

### 封闭测试版

- P0 主流程可用，H5 构建通过。
- 本地数据迁移测试通过。
- 快速记录、今天、收集箱、日程无阻断问题。
- 至少完成基础 Android/iOS 通知验证。

### 公测版

- 所有 P0 UAT 用例通过。
- 无已知任务丢失、错误删除或提醒无法取消问题。
- 正式认证替换明文密码。
- 移除未使用的相机权限。
- 完成隐私政策、数据导出和账号/数据删除。
- 完成 Android/iOS 前台、后台、结束应用、重启和时区变化测试。
- 埋点口径通过数据校验。

### 正式版

- 两周封闭测试达到或接近核心指标。
- 崩溃率、提醒失败率和迁移失败率在可接受范围。
- 用户支持和数据恢复流程可执行。
- 自动课表导入只在准确率和修正率达到门槛后进入默认入口。

## 23. 产品验证计划

### 23.1 原型可用性测试

样本：5–10 名不同年级、不同任务密度的学生。

测试任务：

1. 以新用户身份记录第一项作业，不提前解释导航。
2. 找到一项未来任务和一项尚未规划的任务。
3. 将收集箱任务安排到本周空档。
4. 判断下一项行动。
5. 处理一次提醒。
6. 导入或建立一周课表。
7. 查看本周反馈并解释其含义。

观察指标：导航任务成功率、首次点击正确率、完成率、耗时、错误次数、是否需要提示、用户对课程/任务概念的理解。

### 23.2 两周封闭测试

样本：20–30 名学生。

需要收集：

- 首次激活率。
- 每日创建和完成数量。
- 提醒处理率和稍后次数。
- 逾期任务比例变化。
- 收集箱积压变化。
- 课表导入修正率。
- 用户实际保留的提醒数量。
- 第二周有效执行用户比例。

进入 OCR 开发的建议门槛：至少 40% 的深度测试用户明确需要导入能力，并且标准模板/手动课程录入被证明是主要激活阻力。

## 24. 已确定决策与待确认事项

### 已确定

- 产品面向高校学生个人任务管理。
- 核心闭环为创建—提醒—执行—反馈。
- 目标主导航为今天｜日程｜＋｜任务｜我的；当前“收集箱”一级入口属于待改造基线。
- 收集箱是任务中心的二级标签，不再独占一级导航。
- 中央“＋”打开快速创建底部浮层，完整字段通过渐进展开提供。
- 首次使用先完成真实任务，再逐步引导通知权限、课表和正式账号。
- 今天页以当前/下一项和今日执行队列为首屏，不再以大标题和历史总完成率为核心。
- 周反馈从今天和我的进入，不单独占用一级导航。
- 镜子和手电筒不属于产品范围。
- 提醒不再作为独立主导航。
- 课程/活动与任务分开建模、统一展示。
- 快速创建只要求标题。
- 不以复杂游戏化作为 MVP 核心。

### 待产品负责人确认

以下事项不阻塞数据模型和 P0 原型，但在对应 Sprint 开始前需要确认：

1. 首发优先 Android，还是 Android/iOS 同步公测。
2. 首批测试用户主要来自哪些学校和年级。
3. P0 课表导入是否同时支持 CSV 和 ICS，或只先做一种。
4. 默认课程节次是否采用学校作息模板，还是只使用实际时间。
5. 是否在 P0 引入正式服务端账号与同步。
6. 周反馈默认在周日晚上还是用户自定义时间生成。
7. 任务类型是否需要增加考试、竞赛和求职三个独立类型。

## 26. MVP 完成定义（Definition of Done）

MVP 只有同时满足以下条件才算完成：

- 新用户可以先创建首个任务，再按需完成通知、课表和正式账号引导。
- 一级导航为今天｜日程｜＋｜任务｜我的，并能保留各页滚动和筛选状态。
- 中央“＋”打开快速创建浮层，不强迫用户先进入完整表单。
- 用户可以在任意主页面快速记录任务。
- 无日期任务正确进入“任务 > 收集箱”，并能被重新规划。
- 今天页只展示与今天执行相关的内容。
- 业务页面使用内容优先的中文界面，不以宣传式大标题和历史总完成率占据首屏。
- 用户可以建立课程和固定活动，并在日程中查看。
- 任务可以关联课程，截止时间与计划时间语义明确。
- 提醒与任务绑定，完成、改期和删除能同步处理提醒。
- 用户可完成、稍后、改期，而不是只能勾选完成。
- 系统能识别基础时间重叠并说明冲突原因。
- 今日和本周反馈按本文口径正确计算。
- 旧数据升级不丢失。
- 核心埋点可用于计算北极星指标。
- Android/iOS 核心提醒场景通过真机验证。
- 无明文正式密码、无无关相机权限、具备数据导出和清除能力。

完成以上闭环后，再评估截图 OCR、教务系统适配、智能时间推荐和更丰富的学习激励。
